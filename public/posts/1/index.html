    1st

    Mac OS 上 Git 连接 GitHub 配置#

    在 Mac OS 上配置 Git 连接 GitHub，核心有两种方式：HTTPS 协议（简单易上手，适合新手）和 SSH 协议（免密码登录，更安全高效，适合长期使用）。下面分别详细讲解配置步骤，以及后续的测试和使用方法：

    前提准备#

    1. 已完成 Git 本地配置（用户名/邮箱）：如果还没配置，先执行下面命令（替换为你的 GitHub 账号信息）：
      1. git config --global user.name "你的 GitHub 用户名"
git config --global user.email "你的 GitHub 绑定邮箱"
    2. 已注册 GitHub 账号：没有的话先去 GitHub 官网注册。

    方式一：HTTPS 协议（推荐新手，无需配置密钥）#

    HTTPS 方式无需手动生成密钥，通过 GitHub 账号密码（或个人访问令牌）授权，配合 Mac 钥匙串缓存凭证，后续无需重复输入密码，操作最简单。

    步骤 1：配置凭证缓存（已配置可跳过）#

    之前在本地配置中提到过 Mac 钥匙串缓存，这里再确认一次，确保无需每次输密码：

    git config --global credential.helper osxkeychain

    步骤 2：测试连接（克隆仓库/推送代码）#

    HTTPS 方式无需提前“配置连接”，直接通过 GitHub 仓库的 HTTPS 地址操作，第一次会自动触发授权：

    1. 打开 GitHub 上任意仓库（比如你的个人仓库），点击右上角「Code」，复制「HTTPS」地址（类似 https://github.com/你的用户名/你的仓库名.git）；
    2. 打开 Mac 终端，进入你想存放仓库的目录（比如 cd ~/Documents/Code），执行克隆命令：
      1. git clone https://github.com/你的用户名/你的仓库名.git
    3. 首次执行时，会弹出登录窗口，要求输入 GitHub 用户名 和 密码/个人访问令牌：
      1. 若你的 GitHub 账号开启了「2FA（双因素认证）」：不能用账号密码登录，必须用「个人访问令牌」（下文会讲如何生成）；
      2. 若未开启 2FA：直接输入 GitHub 账号密码即可。
    4. 登录成功后，仓库会自动克隆到本地，后续执行 git pull（拉取）、git push（推送）时，钥匙串会自动复用凭证，无需再输密码。

    关键补充：生成 GitHub 个人访问令牌（2FA 必用）#

    如果开启了 2FA，或想提高安全性，推荐用「个人访问令牌」替代密码：

    1. 登录 GitHub → 点击右上角头像 →「Settings」→ 左侧「Developer settings」→「Personal access tokens」→「Tokens (classic)」→「Generate new token」；
    2. 填写信息：
      1. Note：备注令牌用途（比如「Mac Git 连接」）；
      2. Expiration：设置令牌有效期（推荐选 30 天或自定义，更安全）；
      3. Scopes：勾选权限（至少勾选 repo，用于操作仓库；其他按需勾选）；
    3. 点击「Generate token」→ 复制生成的令牌（只显示一次，务必保存好）；
    4. 克隆/推送仓库时，密码框直接粘贴这个令牌即可。

    方式二：SSH 协议（免密码，长期使用更高效）#

    SSH 方式通过「本地私钥 + GitHub 公钥」配对授权，配置完成后无需输入账号密码，直接连接，更适合频繁操作 GitHub 的场景。

    步骤 1：检查本地是否已有 SSH 密钥#

    先查看是否已经生成过 SSH 密钥（避免重复生成）：

    ls -al ~/.ssh
    • 若输出中包含 id_rsa（私钥）和 id_rsa.pub（公钥），说明已有密钥，直接跳到「步骤 3」；
    • 若没有，则执行「步骤 2」生成密钥。

    步骤 2：生成 SSH 密钥对#

    在终端执行以下命令（替换为你的 GitHub 绑定邮箱）：

    ssh-keygen -t rsa -b 4096 -C "你的 GitHub 绑定邮箱"

    执行后会出现三次提示，全部按回车默认即可：

    1. 提示「Enter file in which to save the key」：默认保存路径 ~/.ssh/id_rsa，无需修改；
    2. 提示「Enter passphrase」：设置密钥密码（可选，建议留空，避免每次用 SSH 都要输密码）；
    3. 提示「Enter same passphrase again」：重复密码（留空则直接回车）。

    生成成功后，~/.ssh 目录下会出现两个文件：

    • id_rsa：私钥（重要！不要泄露给任何人）；
    • id_rsa.pub：公钥（需要上传到 GitHub）。

    步骤 3：复制本地公钥内容#

    用终端命令读取公钥内容并复制（避免手动打开文件复制时出错）：

    pbcopy < ~/.ssh/id_rsa.pub

    执行后，公钥内容已复制到剪贴板（无需额外操作，下一步直接粘贴）。

    步骤 4：在 GitHub 添加 SSH 公钥#

    1. 登录 GitHub → 点击右上角头像 →「Settings」；
    2. 左侧菜单找到「SSH and GPG keys」→ 点击右上角「New SSH key」；
    3. 填写表单：
      1. Title：备注公钥来源（比如「MacBook Pro」）；
      2. Key type：默认「Authentication key」；
      3. Key：粘贴刚才复制的公钥内容（确保没有多余空格或换行）；
    4. 点击「Add SSH key」，完成添加（若 GitHub 要求验证密码，输入账号密码即可）。

    步骤 5：测试 SSH 连接是否成功#

    在终端执行以下命令，测试是否能正常连接 GitHub：

    ssh -T git@github.com
    • 首次执行会提示「Are you sure you want to continue connecting (yes/no)?」，输入 yes 按回车；
    • 若输出 Hi 你的GitHub用户名! You've successfully authenticated, but GitHub does not provide shell access.，说明连接成功！

    两种连接方式对比（选择建议）#

    特性HTTPS 协议SSH 协议
    配置难度极低（无需密钥）中等（需生成/配置密钥）
    登录方式账号密码/个人访问令牌（2FA 必用令牌）免密码（密钥配对）
    安全性较高（依赖 HTTPS 加密）更高（密钥配对，无密码传输）
    适用场景新手、偶尔使用 GitHub频繁操作 GitHub、追求高效
    • 新手推荐先选 HTTPS 方式，快速上手；
    • 长期开发、频繁推送代码，推荐 SSH 方式，免密码更高效。

    切换连接方式（若已用一种，想换另一种）#

    如果之前用 HTTPS 克隆了仓库，想换成 SSH 连接，无需重新克隆，只需修改本地仓库的远程地址：

    1. 进入本地仓库目录：
      1. cd 你的仓库目录路径
    2. 查看当前远程地址（确认是 HTTPS 还是 SSH）：
      1. git remote -v
    3. 修改远程地址为 SSH 格式（复制 GitHub 仓库的 SSH 地址）：
      1. git remote set-url origin git@github.com:你的用户名/你的仓库名.git
    4. 验证修改是否成功：再次执行 git remote -v，若显示 git@github.com 开头的地址，说明切换成功。

    常见问题排查#

    1. SSH 连接失败：Permission denied (publickey)#

    • 原因：公钥未正确添加到 GitHub，或私钥权限过高/过低；
    • 解决：
      • 重新检查 GitHub 上的公钥是否和本地 id_rsa.pub 一致（重新复制粘贴一次）；
      • 修复私钥权限（Mac 下私钥权限太开放会被 SSH 拒绝）：
        1. chmod 600 ~/.ssh/id_rsa
      • 重新测试连接：ssh -T git@github.com。

    2. HTTPS 方式推送时提示密码错误（已开启 2FA）#

    • 原因：开启 2FA 后，GitHub 不再支持账号密码直接登录，必须用个人访问令牌；
    • 解决：按「方式一」的「生成个人访问令牌」步骤创建令牌，推送时用令牌替代密码。

    3. 克隆仓库时提示「fatal: unable to access ‘https://github.com/...'」#

    • 原因：网络问题（比如墙）或代理配置；
    • 解决：
      • 检查网络是否能访问 GitHub（浏览器打开 GitHub 测试）；
      • 若用代理，配置 Git 代理（替换为你的代理地址和端口）：
        1. # HTTP 代理（比如 clash 的默认代理）
git config --global http.proxy http://127.0.0.1:7890
git config --global https.proxy http://127.0.0.1:7890
      • 无需代理时，取消代理配置：
        1. git config --global --unset http.proxy
git config --global --unset https.proxy

    配置完成后，你就可以通过 git clone（克隆仓库）、git push（推送本地代码到 GitHub）、git pull（拉取 GitHub 代码到本地）等命令，正常用 Git 管理 GitHub 上的项目了！
